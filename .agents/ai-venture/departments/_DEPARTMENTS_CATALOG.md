# Departments

Canonical routing catalogue. Departments are agent perspectives, not organizational headcount.
Read the Lead and consulted definitions before substantive work; optional Venture overlays live in
`.agents/departments/` only when durable local knowledge exists.

| Department | Leads when the requested outcome primarily concerns |
| --- | --- |
| [Management](management.md) | Direction, priorities, Products, pricing strategy, Goals, Roadmap, or Venture-wide trade-offs |
| [UX](ux.md) | Usability, interaction, accessibility, or the experience of a Product |
| [Engineering](engineering.md) | Creating or changing technical systems, Products, or production methods |
| [Architecture](architecture.md) | Boundaries between parts, dependency direction, contracts others rely on, or commitments that are expensive to reverse |
| [Quality](quality.md) | Quality criteria, verification, defects, correctness, or reliability |
| [Security](security.md) | Malicious threats, vulnerabilities, access, protection, or security incidents |
| [Safety](safety.md) | Accidental harm, hazards, likelihood, severity, controls, or safe failure |
| [Marketing](marketing.md) | Markets, positioning, brand, public identity, awareness, or demand |
| [Sales](sales.md) | Acquisition channels, offers, listings, transactions, contracts, or closing |
| [Support](support.md) | Feedback intake, deduplication, user communication, or closure |
| [Finance](finance.md) | Economics, budgets, cash, accounting, tax, or financial controls |
| [Legal](legal.md) | Legal obligations, contracts, compliance, privacy law, or regulatory response |
| [HR](hr.md) | Human employment, hiring, development, performance, or workplace obligations |
| [Operations](operations.md) | Repeatable production, delivery, availability, incidents, or daily running |

Routing is outcome-based. Select exactly one Lead per phase and only material consulted
Departments. The detailed contract is in `../standards/venture-operating-model.md`.
