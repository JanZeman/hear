# Product vision

HEAR is a game whose visual fantasy can vary radically while the underlying listening task remains identical.

The user should be able to start quickly, choose a world because it looks inviting, and enter it with almost no front-loaded explanation. Headphones are recommended, not required. The application should not ask for unrelated data or permissions before the user understands the value of the experience.

## Experience principles

- **Immediate attraction:** the world selector should sell the experience before setup is requested.
- **Zero-frontload onboarding:** explain only what is needed at the moment it becomes necessary.
- **Sound first:** the auditory event, not a visual cue, is what tells the player when to respond.
- **World-consistent success:** a correct response causes a satisfying event natural to that world.
- **No dexterity tax:** aiming precision, reaction accuracy, or motor skill must not decide whether a valid hearing response counts.
- **Same measurement, different fantasy:** worlds may be calm, comic, cinematic, abstract, adult or childlike.
- **Responsive by design:** worlds reveal/reframe/reflow; artwork is not stretched to fit.
